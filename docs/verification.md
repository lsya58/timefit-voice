# 実機検証チェックリスト

`samples/full_test.srt`（30行・約2分16秒）と `samples/full_test.csv`（話者3人・8行）で、主な機能をひととおり確認する。
所要時間の目安は30〜40分。結果はページ末尾の「報告テンプレート」に書く。

> 状態（等倍・話速調整・要約など）は、話者や VOICEVOX のバージョンで変わる。下の表の「狙い」は目安で、ぴったり一致しなくてよい。
> 見るべきなのは「おかしな音にならないか」「表示と実際の音声が合っているか」。

---

## テスト1: 字幕30行（メインの検証）

設定: 話者 ずんだもん（ノーマル）/ ぴったり / 話速の上限 1.30 / AI 要約 ON

1. `python main.py` で起動し、`samples/full_test.srt` をドロップして「尺合わせを開始」
2. 処理中: 行が順に「処理中」になり、上の帯の色が変わっていくこと。中止ボタンが出ていること
3. 完了後、下の表を見ながら試聴（▶）する

| 行 | 狙い | 確認すること |
|---|---|---|
| 1〜3 | そのまま収まる | 「発話 ○s ＋ 無音 ○s」の表示。1と2は隙間なく続く |
| 2 | 話速調整 | 早口すぎないか（耳で聞いて許容範囲か） |
| 4 | AI 要約 | 確認画面で「パクス・トクガワーナ」など消えた語の警告が出る |
| 5, 24, 26 | 数字の読み | 「1600年」「1853年」「1867年」を正しく読むか |
| 6 | 枠が極端に短い（1.5秒） | 要約されて収まるか、「⚠ 収まらず」になるか。どちらでもよいが、表示が正しいこと |
| 7 | 枠が長い（15秒） | 無音が大きく足される（バーの斜線部分が長い） |
| 8 | 2行の字幕・`<i>` タグ | タグが読み上げられず、2行がつながって読まれる |
| 9 | 疑問文 | 語尾が上がるなど、不自然でないか |
| 11〜15 | 短い行が連続 | テンポよくつながるか |
| 16 | アルファベット | 「VOICEVOX」の読み方（ボイスボックス等）。気になれば辞書登録を案内する |
| 17 | 「100万人」 | 数字の読み。枠がきついので話速調整か要約になるはず |
| 18 | 長いカタカナ固有名詞 | 「パクス・トクガワーナ」を読めるか |
| 19, 20, 27 | 固有名詞の多い長文 → 要約 | 確認画面で消えた語（井原西鶴・葛飾北斎など）の警告が出る |
| 21, 22 | 0.6秒・1.0秒の極短 | 音が途切れたり、はみ出したりしないか |
| 22→23 | 5秒の空白 | combined.wav でその間が無音になっている |
| 全体 | — | 上の時間軸の目盛りが分単位で表示される。ログの最後に「処理時間の内訳」が出る |

4. **確認画面**（19行目で試す）
   - 「✎ AI が書き換えました · 確認する」を押す → 3案に推定秒数と「消えた語 n」が出る
   - 案2を選んで「この文で作り直す」→ 行が更新され、トーストに「出力ファイルも更新済み」と出る
   - 出力フォルダの `fitted.srt` の19番が新しい文になっている。`combined.wav` の該当箇所も新しい音声になっている
   - 「AI に別の案を出してもらう」で案が増える
   - 手書き欄にわざと長い文を入れる → 「⚠ … でも収まりません」と出る。そのまま作り直すと「⚠ 収まらず」になる
   - 「元の原稿に戻す」で原文に戻る
5. 「まとめて再生」で全体を通して聞き、つなぎ目に「プツッ」という音や、変な間がないか

## テスト2: AI 要約 OFF

同じ `full_test.srt` を、AI 要約を OFF にしてもう一度実行する。
- 要約が必要だった行（4・19・20・27 など）が「⚠ 収まらず」になり、バーのはみ出し部分が赤い斜線で表示される
- 行に「要約がオフです。目標より ○秒 長いです」と出る
- 「✎ 原稿を短くする」から手で短くして作り直せる

## テスト3: 「以内」モード

「以内」で1回実行する。
- 「＋ 無音」の表示が出ない。行ごとの WAV が目標より短いままになっている
- `combined.wav` は字幕の時刻どおりに並んでいる（途中の無音はある）

## テスト4: CSV・話者3人

`samples/full_test.csv` を実行する（話者は「ずんだもん」を選んでおく）。
- 原稿の左に話者名（四国めたん・春日部つむぎ）が出る。実際にその声で読まれる
- 6行目（話者ID 空欄）は画面で選んだ話者で読まれる
- `#` で始まる行は読まれない。`"…、…"` で囲んだカンマ入りの原稿が1つの文として読まれる
- `credits.txt` に3人分のクレジットが出る
- **Excel で開いて「CSV」（Shift_JIS）で保存し直し**、もう一度読み込めること

## テスト5: 動画編集ソフトに戻す（販売デモの主役）

1. 動画編集ソフトに `samples/full_test.srt` を字幕として読み込む
2. 出力フォルダの `combined.wav` を、タイムラインの 0秒の位置に置く
3. 再生して、各セリフが字幕の表示中に話し終わっていることを確認する（字幕1つ分の区間に収まっていればOK。単語単位の同期は対象外）
4. 字幕を `fitted.srt` に差し替えると、要約後の文と音声が一致すること

## テスト6: 異常時

- VOICEVOX を終了した状態で実行 → 「VOICEVOX を起動してから…」と出る。右上が「エンジン未起動」になり、クリックで再接続できる
- 処理中に「中止する」→ 今の行が終わったら止まり、そこまでの結果が書き出される
- 設定で APIキーを間違った値にして実行 → 「APIキーが正しくない…」と出る（確認後、正しいキーに戻す）

## テスト7: exe・別の PC

1. `.\scripts\build.ps1 -Edition free` で無料版を作る
2. Python の入っていない PC（または別の Windows ユーザー）で `TimeFitVoice_Free.exe` を起動
3. 「サンプル字幕で試す」が動く。`full_test.srt` を読み込むと「無料版は先頭 10 行まで」と出て、10行で止まる
4. ウイルス対策ソフトの警告が出たかどうかを記録する

## v0.4.2 で追加した確認（任意）
- `full_test.csv` の1行の話者IDを `999` に変えて実行 → 処理を始める前に「使えない話者IDがあります … 話者ID 999」と出て、1行も作られないこと
- 処理後のログに「※ 音声合成に、話している時間の約○倍かかっています」が出たら、VOICEVOX の設定（GPU モード / CPU スレッド数）を変えて、もう一度時間を比べる
