# プロジェクト概要: TimeFit Voice (仮称)
**〜動画編集における「尺合わせ」のペインを解消する自動音声生成ツール〜**

> 現状の実装とのずれ、必要な拡張、製品化・収益化の方針は [product_strategy.md](product_strategy.md) を参照。

## 1. プロジェクトのビジョンと提供価値
本プロジェクトは、YouTube動画、TikTok、Vlogなどのクリエイター向けに**「指定した動画の尺（秒数）に、音声（VOICEVOX）を1ミリ秒単位でピッタリ収める」**ことを自動化するデスクトップツールを開発・販売（BOOTH等を想定）するプロジェクトである。

### 解決する強烈なペイン（課題）
現在の動画制作フローにおいて、クリエイターは以下の手作業に多大な時間を奪われている。
* 「映像の尺」に対して台本が長すぎる場合、動画編集ソフト上で音声をカットし、不自然に早送りする。
* それでも収まらない場合、台本を削ってVOICEVOXに戻り、再度音声を書き出して動画編集ソフトに配置し直す。
* この「トライ＆エラーの往復作業」が、動画1本あたり数十回発生している。

### コアバリュー（提供価値）
**「テキストと目標秒数を投げるだけで、意味を保ったまま尺に収まったWAVが返ってくる魔法のブラックボックス」**
ユーザーはPythonやAPIの知識がゼロでも、GUIから実行するだけでこの恩恵を受けられる。

## 2. コア・アルゴリズム（時間調整の段階的ロジック）
本ツールの心臓部は、LLM（Gemini）の要約力と音声合成エンジンの話速制御を掛け合わせた以下のアルゴリズムである。

1. **長さの見積もり**: VOICEVOX の `audio_query` の結果（各モーラ・間の長さ）を足し合わせ、合成せずに等倍の秒数を見積もる。収まればそのまま合成。
2. **間を詰める**: 句読点の間（`pauseLengthScale`、対応エンジンのみ）を最小 0.6 倍まで詰めて収まるか判定。
3. **話速の調整**: `必要話速 <= 上限（既定1.3倍）` なら話速を上げる。合成後に実際の長さを測り、はみ出していれば上限内で話速を上げ直す。
4. **LLMによる要約**: 上限でも収まらなければ Gemini（モデル名は設定で変更可）に、見積もり秒数と原稿の文字数から逆算した文字数で要約させ、1〜3 をやり直す（既定3回まで。2回目以降は前回案を渡してさらに短くさせる。要約は常に元の原稿から行う）。
5. **最終アジャストメント**: 足りない分は末尾に無音を足し、80ms 以内のはみ出しは末尾の無音を削って、サンプル単位で目標の長さに一致させる（「以内」モードでは無音を足さない）。それでも収まらない行は削らずに「収まらず」として報告する。

## 3. システム・アーキテクチャと特殊な開発フロー
本プロジェクトは、開発体験（DX）とWindowsネイティブアプリとしての確実な動作を両立させるため、以下の厳格なワークフローを採用している。
**※注意: AIアシスタントは、この環境分離の原則を破る提案（WSLからのネットワークブリッジ解決策など）をしてはならない。**

* **開発環境 (VS Code + WSL2)**: コードの執筆、バージョン管理（Git）、ドキュメント作成を行う。
* **実行・テスト環境 (Windows PowerShell)**: `git pull` でコードを取得後、WindowsネイティブのPython仮想環境（venv）で実行する。これにより、ローカルで稼働するVOICEVOX (`127.0.0.1:50021`) へネットワークの壁なしで直接通信する。
* **技術スタック**:
  - Python 3.12
  - `google-genai` (Gemini API公式SDK)
  - `requests` (VOICEVOX HTTP API通信用)
  - `pywebview` (GUI。HTML/CSS で画面を描き、Windows 標準の Edge WebView2 で表示する。exe はほぼ大きくならない)
  - `PyInstaller` (.exe化用)、`pytest` (テスト)
* **コード構成** (`timefit/`):
  - `fitter.py` 尺合わせの判断（間を詰める → 話速 → 要約）。通信しないのでテストしやすい
  - `engine.py` VOICEVOX 通信と `audio_query` からの長さ見積もり / `llm.py` Gemini 要約
  - `audio.py` WAV のメモリ上処理 / `inputs.py` CSV・SRT・VTT / `outputs.py` 書き出し
  - `batch.py` 一括処理（CLI・GUI 共通）/ `cli.py` / `config.py` / `edition.py`（無料版・製品版）
  - `ui/app.py` 画面と Python の橋渡し / `ui/web/` 画面の HTML・CSS・JS（ダークテーマ、タイムライン表示）
  - `main.py` 引数なしで GUI、引数ありで CLI
* **テスト**: `tests/` は VOICEVOX と Gemini を偽物に差し替えて動くので、WSL 上で `python -m pytest` できる（実機の確認は Windows 側で行う）。
* **配布物のビルド**: Windows で `.\scripts\build.ps1 -Edition pro`（または `free`）。

## 5. AIアシスタントへの開発ガイドライン
本プロジェクトをサポートするAIは、以下の原則を遵守してコードを生成すること。
1. **保守性の優先**: 複雑な非同期処理（asyncio）や過剰なマルチスレッド化は避け、エラーの追いやすさとロジックの透明性を優先する。
2. **非エンジニア目線のUX**: エラーログはスタックトレースをそのまま吐き出すのではなく、「VOICEVOXを起動してください」「GeminiのAPIキーが間違っています」など、一般ユーザーが自力で解決できる日本語メッセージを標準出力に出すこと。
3. **副作用のないコード**: 関数は単一責任の原則に従い、入力に対して予測可能な出力のみを返すように小さく保つこと。
